## 方法1: 排除法逐步缩小范围

### 推理模式
```
排除...后剩下...
先排除 A 现象，再排除 B 条件，最终锁定 C 原因
```

### 应用场景
- 系统异常重启定位
- 通信故障排查
- 外设不工作诊断

### 推理链示例
```
系统异常重启
→ 排除上电复位 (PORRSTF=0)
→ 排除外部复位 (PINRSTF=0)
→ 排除欠压复位 (BORRSTF=0)
→ 剩下看门狗复位 (IWDGRSTF=1)
→ 定位: 初始化阶段未喂狗导致超时
→ 验证: 3分钟监听脚本确认 IWDGRSTF 触发
```

### 来源案例
- HelpPort - 利用看门狗复位实现12秒稳定亮屏 (2026-07-08)

## 方法2: 对比法找差异

### 推理模式
```
正常时 A，异常时 B → 差异点即根因
对比两个版本/两种状态，找出关键差异
```

### 应用场景
- 版本升级引入的 BUG
- 硬件变更导致的问题
- 配置差异引发异常

### 推理链示例
```
ST-Link 连接时正常，断开后异常
→ 对比: 接 ST-Link 时 VCC/SWDIO 有上拉
→ 差异: ST-Link 的 VTref 接住芯片初始电平
→ 根因: 电源上升时间不够快 / NRST 电容不合适
→ 解决: 断开 ST-Link 独立上电测试确认
```

### 来源案例
- HelpPort - ST-Link 对启动时序的影响 (2026-07-08)

## 方法3: 信号完整性推理

### 推理模式
```
现象 X 在条件 Y 下出现 → 可能是信号完整性问题
提高频率/延长线缆后异常 → 反射/串扰/振铃
```

### 应用场景
- 高速信号 (SPI/USB/ETH) 不稳定
- 长距离通信异常
- 特定条件下偶发错误

### 推理链示例
```
SPI 从 /32 改到 /16 黑屏
→ 频率从 2.625MHz 升到 5.25MHz
→ 20cm FPC 排线 + 高速 → 信号反射
→ 验证: 示波器看 SCK 有过冲/振铃
→ 解决: 降低 GPIO 压摆率 或 保持 /32
```

### 来源案例
- HelpPort - SPI 波特率与信号完整性 (2026-06-25)

## 方法4: 时序竞争分析

### 推理模式
```
A 事件和 B 事件几乎同时发生 → 竞态条件
osDelay 期间状态被其他任务修改 → 时序错乱
```

### 应用场景
- 多任务系统状态不一致
- 中断和任务间数据竞争
- 状态机时序错乱

### 推理链示例
```
倒计时结束后红灯不亮
→ 分析: osDelay(1000) 期间 Counter_Run 继续减
→ 竞态: competition() 拿着旧状态醒来
→ 根因: 先延迟再设标志 → 醒来时状态已变
→ 解决: 先设标志再延迟
```

### 来源案例
- WSC-16 - osDelay 阻塞导致竞态条件 (2026-06-23)

## 方法5: 分层排除法 (自底向上)

### 推理模式
```
从硬件层开始逐层向上排查:
物理层 → 协议层 → 应用层
```

### 应用场景
- 通信链路故障
- 外设不响应
- 系统启动失败

### 推理链示例
```
Modbus 设备无响应
→ 物理层: 供电正常? 接线正确? A-B 未接反?
→ 信号层: 波特率匹配? 示波器看波形?
→ 协议层: CRC 正确? 地址正确?
→ 应用层: 485 收发切换? RTS 时序?
→ 定位: RTS 切换后等待时间不足
```

### 来源案例
- WSC-16 - Modbus RTU 通信调试 (2026-06-23)

## 方法6: 假设-验证循环

### 推理模式
```
可能是 X → 设计实验验证 → 确认/排除 → 下一个假设
```

### 应用场景
- 偶发 BUG 定位
- 多因素耦合问题
- 未知根因的复杂故障

### 推理链示例
```
断电 5s 再上电需 40s 亮屏
→ 假设1: 残压导致 POR 未触发 → 加放电电阻测试
→ 假设2: SDRAM 不 ready 死等 → 加超时返回
→ 假设3: IWDG 30s 超时复位 → 读 RCC_CSR 确认
→ 验证: 41s = 30s IWDG + 11s 正常启动
→ 解决: 放电电阻 + SDRAM 超时 + LCD_Init 重试
```

### 来源案例
- HelpPort - 上电残压导致 POR 异常 (2026-07-08)

## 方法7: 数据流追踪

### 推理模式
```
从数据产生到消费全链路追踪:
中断接收 → 缓冲区 → 解析 → 处理 → 响应
```

### 应用场景
- 串口数据丢失/错位
- 协议解析错误
- 缓冲区溢出

### 推理链示例
```
串口屏偶尔不响应
→ 追踪: USART3 单字节中断接收
→ 发现: 刷卡时 MFRC522 13.56MHz 干扰
→ 路径: 干扰 → 串口错帧 → 屏幕解析失败
→ 解决: 帧长度校验 + 刷卡后延迟 200ms
```

### 来源案例
- SX-MK-010 - 电阻屏 UART 受 RFID 干扰 (2026-07-10)

## 方法9: 状态机分析

### 推理模式
```
画出状态转换图:
当前状态 + 输入条件 → 下一状态
找出非法转换/遗漏转换
```

### 应用场景
- 状态机 BUG
- 流程逻辑错误
- 条件覆盖不全

### 推理链示例
```
停止后重刷卡继电器吸合
→ 状态: TFT停止 → 继电器OFF + 保存剩余时间
→ 输入: 再刷卡 → RFID_RUN2 检查 experiment_duration>0
→ 转换: 重启倒计时+继电器ON → 覆盖停止
→ 遗漏: 停止路径未清 experiment_duration
→ 解决: 所有停止路径添加 experiment_duration=0
```

- SX-MK-010 - 竞态条件调试方法 (2026-07-10)

## 方法10: 编码陷阱识别

### 推理模式
```
文件编码 + 编辑方式 → 潜在陷阱
GB2312/UTF-16/BOM → 字节安全编辑
```

### 应用场景
- 中文注释乱码
- 编译报错 (编码问题)
- 文件内容异常

### 推理链示例
```
编辑 gpio.c 后编译报错
→ 检查: 文件头 18 1B 03 1A → UTF-16LE BOM (FF FE)
→ 根因: 按 ASCII 编辑破坏双字节编码
→ 解决: 用支持 GB2312 的编辑器 / 只改 ASCII 部分
→ 验证: 读回文件确认中文正常
```

## 方法11: 中断优先级与临界区分析

### 推理模式
```
ISR 优先级 + 临界区保护 → 是否会被打断?
taskENTER_CRITICAL 屏蔽所有中断 → 高优先级 ISR 被阻塞
```

### 应用场景
- 中断丢失
- 通信时序异常
- 实时性不足

### 推理链示例
```
触摸卡顿
→ 分析: taskENTER_CRITICAL 保护 I2C 读取
→ 矛盾: AD7606 ISR 优先级 5 可打断临界区
→ 后果: I2C 时序被打断 → 触摸数据错误
→ 解决: 移除 taskENTER_CRITICAL / 用互斥锁
```

### 来源案例
- HelpPort - FreeRTOS 临界区与中断优先级 (2026-07-04)

## 方法12: 功耗/热分析

### 推理模式
```
异常行为 + 时间/温度 → 可能是热问题
长时间运行后异常 → 温升导致
```

### 应用场景
- 系统随机重启
- 性能逐渐下降
- 特定时间后异常

### 推理链示例
```
系统运行一段时间后复位
→ 排除: 看门狗 (喂狗正常)
→ 排查: 电源芯片温升 → 过热保护
→ 验证: 加散热片后问题消失
```

## 方法13: 版本对比法

### 推理模式
```
git diff 两个版本 → 找出引入问题的 commit
二分法定位: git bisect
```

### 应用场景
- 新版本引入的 BUG
- 回退确认问题来源
- 多版本并行开发

### 关键命令
```powershell
# 对比两个版本
git diff HEAD~5 HEAD -- path/to/file.c

# 查看文件历史
git log --oneline -- path/to/file.c

# 二分法定位
git bisect start
git bisect bad HEAD
git bisect good v1.0
# 自动测试后标记 good/bad
git bisect reset
```

### 来源案例
- SX-MK-010 - 对比 NEW 和 yuan 仓库 (2026-07-14)

## 方法14: 外设寄存器级调试

### 推理模式
```
现象 → 定位外设 → 读寄存器 → 分析状态位
```

### 应用场景
- 外设不工作
- 通信异常
- 中断未触发

### 推理链示例
```
UART5 不发送
→ 读 USART5_SR: TXE=0 (数据未转移到移位寄存器)
→ 读 USART5_CR1: UE=1, TE=1 (使能正常)
→ 查波特率: BRR 值是否正确?
→ 定位: PCLK 频率不对 → BRR 计算错误
```

### 来源案例
- WSC-16 - UART5 RS485 控制逻辑 (2026-06-23)

## 方法15: 内存布局分析

### 推理模式
```
HardFault → 分析堆栈 → 定位非法地址
.map 文件 → 符号地址 → 确定出错函数
```

### 应用场景
- HardFault 定位
- 栈溢出检测
- 内存越界

### 关键命令
```powershell
# 从 .axf 提取符号表
& "fromelf.exe" -s "Objects\app.axf" > symbols.txt

# 从 .map 文件查找地址对应符号
Select-String -Path "Objects\app.map" -Pattern "0x08001234"

# 栈水位检测 (运行时)
# uxTaskGetStackHighWaterMark(xTaskHandle)
```
