# 001: TFT SPI信号完整性导致显示异常

## 项目
HelpPort (STM32F407VET6 + LT7580 LCD + SPI1 + DMA2)

## 环境
MCU: STM32F407VET6, LCD: LT7580 1024×600, SPI: SPI1硬件驱动, DMA2

## 现象
LCD显示花屏、颜色异常、数据错位

## 影响范围
整个GUI显示功能

## 排查过程

### 假设1: SPI模式不匹配
- 验证方法：检查LT7580时序要求 CPOL=High, CPHA=2Edge (Mode 3)
- 结果：LVGL已配置SPI1+DMA2，模式正确

### 假设2: FMC与SPI冲突
- 验证方法：检查FMC_LCD和SPI1引脚复用
- 结果：FMC用于数据总线，SPI用于命令/参数，无冲突

### 假设3: DMA传输时序问题
- 验证方法：检查DMA2_Stream3(SPI1_TX)配置
- 结果：DMA配置正确

### 假设4: 硬件走线/信号完整性
- 验证方法：检查PCB走线长度、阻抗匹配
- 结果：高速SPI信号走线过长导致信号反射

## 根因
SPI信号走线过长导致信号反射和时序偏移，LCD采样到错误数据

## 修改方案
```c
// 降低SPI速率
SPI1->CR1 &= ~SPI_CR1_BR;
SPI1->CR1 |= SPI_CR1_BR_2; // 分频到合适速率

// 增加信号完整性措施
// - 缩短走线长度
// - 添加串联匹配电阻(22-33Ω)
// - 降低SPI边沿速率
```

## 验证结果
显示正常，无花屏/颜色异常

## 预防措施
- 高速信号走线尽量短
- 添加串联终端匹配电阻
- 必要时降低SPI速率

## 经验规则
- SPI速率不是越快越好，需考虑走线长度
- 1024×600屏用SPI需特别注意信号完整性
- 花屏/颜色异常→先查时序再查硬件
