# 006: 摄像头TCP连接成功但命令超时

## 项目
WIFI_CAM (Python + WIFL_8K摄像头)

## 环境
WiFi: 192.168.1.1, 协议: TCP命令+UDP视频流

## 现象
TCP连接成功但命令0x50/0x10发送超时，摄像头信息获取失败

## 影响范围
摄像头控制和视频流功能

## 排查过程

### 假设1: 网络不通
- 验证方法：ping 192.168.1.1
- 结果：网络可达

### 假设2: 端口被防火墙拦截
- 验证方法：检查5000/5001端口
- 结果：TCP 5000连接成功

### 假设3: 协议格式不对
- 验证方法：抓包分析摄像头返回数据
- 结果：摄像头返回了SSID/IP/型号信息但命令格式不匹配

## 根因
**协议格式不匹配**。摄像头期望的命令格式与脚本发送的不一致，导致摄像头不响应。

## 修改方案
```python
# 分析摄像头返回的原始数据
# 调整命令格式:
# - 检查帧头/帧尾
# - 检查校验和算法
# - 检查命令字节顺序
# 用Wireshark抓包对比正常通信
```

## 验证结果
调整协议格式后命令正常响应

## 预防措施
- 新设备先用串口/Wireshark抓包分析协议
- 注意字节序(大端/小端)
- 校验和算法需与设备一致

## 经验规则
- TCP连接成功≠协议正确
- 命令超时通常是协议格式错误
- 抓包是调试网络协议的最佳手段
