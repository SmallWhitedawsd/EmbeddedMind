# 002: 看门狗复位实现12秒稳定亮屏方案分析

## 项目
HelpPort (STM32F407VET6 + LT7580 + IWDG)

## 环境
MCU: STM32F407VET6, LCD: LT7580, 看门狗: IWDG (LSI~32kHz)

## 现象
用户提出：如果启动不正常11秒才亮屏，能否加1秒后触发看门狗复位，让每次上电都稳定12秒亮屏？

## 影响范围
启动可靠性

## 排查过程

### 假设: 1s强制复位可解决问题
- 验证方法：分析LT7580上电稳定时间
- 结果：**不可靠！** 关键点是"第二次能成功不是因为复位这个动作，而是因为过了30s LT7580电源/内部状态终于稳了"

### 反证
- 软复位/IWDG复位不会让LT7580重新上电
- 1s时强制复位，LT7580仍不稳定→第二次仍可能卡Check_SDRAM_Ready
- 最坏情况：进入"每30s复位一次"的启动循环

## 根因
LT7580需要完整掉电才能有效POR。断电5s时内部状态未放尽，MCU复位无法让LT7580重新初始化。

## 修改方案
**正确方案：给状态轮询加超时+重试**
```c
// 每个Check_xxx加500ms超时
// LCD_Init最多5次重试（每次LCD_Reset硬件复位LT7580）
// 效果：坏启动1~2s内自恢复，稳定~12s点亮
```

## 验证结果
- 坏启动不再等30s IWDG
- ~2s内自检恢复重试
- 最坏5次重试<5s，远小于30s IWDG

## 预防措施
- 不要依赖复位解决硬件初始化问题
- 硬件状态轮询必须有超时
- 理解"复位"vs"重新上电"的本质区别

## 经验规则
- 软复位≠硬件复位≠重新上电
- 控制器内部状态残留是热启动问题的常见根因
- 解决启动问题的正确方向是超时+重试，不是强制复位
