# 001: OV7670 TFT显示黄色底黑色噪点

## 项目
OV7670_TFT (STM32F103C8T6 + OV7670 + ST7735S 1.77寸 TFT)

## 环境
MCU: STM32F103C8T6, 摄像头: OV7670, 显示: ST7735S 128×160, 无FIFO

## 现象
上电白屏→黄色底+黑色噪点→七八秒后刷新显示噪点，能大致看到手轮廓

## 影响范围
摄像头实时显示功能完全不可用

## 排查过程

### 假设1: SPI时钟过快损坏数据
- 验证方法：TFT SPI从36MHz降到9MHz
- 结果：黄色底→有变化但仍异常

### 假设2: MADCTL BGR位导致R/B通道交换
- 验证方法：MADCTL 0xC8→0xC0 (BGR=1→0)
- 结果：黄色→蓝色，确认BGR位有效

### 假设3: 0x3A寄存器TS位选择错误色彩路径
- 验证方法：0x3A 0x84→0x04 (TS=1→0)
- 结果：蓝色→浅蓝色，仍偏蓝

### 假设4: PLL被旁路，传感器时钟不足
- 验证方法：0x6B 0x00→0x4A (启用PLL ×4)
- 结果：出现真实颜色但五彩斑斓交织

### 假设5: PCLK过快导致SPI写入赶不上消隐期
- 验证方法：0x11 0x9F→0xBF (PCLK 625kHz→312.5kHz)
- 结果：颜色出现但仍有噪点

### 假设6: COM15(0x40)设为RGB555而非RGB565
- 验证方法：0x40 0xF0→0xD0 (RGB555→RGB565)
- 结果：白色显示正确，黑色偏粉

### 假设7: PCLK预同步导致整行字节偏移
- 验证方法：移除`while(PCLK==1);while(PCLK==0);`预同步
- 结果：显示正常

## 根因
**7个问题叠加**：
1. SPI 36MHz损坏TFT数据
2. MADCTL BGR=1交换R/B通道
3. PLL旁路(0x6B=0x00)传感器时钟不足
4. COM15=0xF0是RGB555非RGB565
5. PCLK过快SPI越界
6. 预同步导致整行hi/lo字节错位
7. 增益寄存器0x01/0x02被砍半

## 修改方案
```c
// TFT.c - SPI降频+BSY等待
SPI1->CR1 &= ~SPI_CR1_BR;
SPI1->CR1 |= SPI_CR1_BR_0 | SPI_CR1_BR_1; // 9MHz
while(SPI1->SR & SPI_SR_BSY); // 等待移位寄存器

// TFT.c - MADCTL
LCD_WriteCmd(0x36); LCD_WriteData(0xC0); // BGR=0

// OV7670.c - 关键寄存器
{0x6B, 0x4A},  // PLL ×4 = 20MHz
{0x40, 0xD0},  // RGB565 (核心修复!)
{0x11, 0xBF},  // PCLK = 312.5kHz
{0x3A, 0x04},  // 标准TSLB
{0x01, 0x80},  // 蓝色增益恢复默认
{0x02, 0x80},  // 红色增益恢复默认

// main.c - 预热5秒
Delay_ms(5000); // AWB收敛
```

## 验证结果
TFT纯色测试通过→摄像头实时显示正常→颜色正确无噪点

## 预防措施
- OV7670寄存器配置需对照手册逐位验证
- SPI速率不超过外设最大值
- 摄像头需预热等待AWB收敛

## 经验规则
- COM15[5:4]=01是RGB565，=11是RGB555（常见混淆）
- PCLK消隐期必须 > SPI写入时间
- 任何PCLK同步逻辑都可能导致整行字节偏移
