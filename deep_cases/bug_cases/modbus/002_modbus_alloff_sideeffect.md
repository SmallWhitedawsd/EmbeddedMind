# 002: Modbus写0关闭全部导致ULN2003A状态异常

## 项目
WSC-16 (STM32F103 + Modbus RTU + ULN2003A)

## 环境
MCU: STM32F103, 驱动: ULN2003A, 12路继电器输出

## 现象
Modbus写0关闭全部插座时，出现意外行为

## 影响范围
所有12路SOCKET输出

## 排查过程

### 假设1: 写0=所有bit=0→所有引脚低→ULN2003A输出高阻
- 验证方法：分析Power_control函数
- 结果：power_ctrl=0 → PowerControlState低12位全0 → 所有PD/PE引脚低

### 假设2: 引脚复用冲突
- 验证方法：检查PD14/PD15是否与其他功能复用
- 结果：PD14=SOCKET5(桌面照明), PD15=SOCKET6(灯带照明)

## 根因
写0→所有bit=0→所有MCU引脚低→ULN2003A输出高阻→继电器断开→灯灭。逻辑正确但需注意：
- 上位机和本地按键操作的是同一个PowerControlState变量
- 按键是XOR翻转，上位机是直接覆盖

## 修改方案
```c
// 按键和上位机共用PowerControlState
// 按键: XOR翻转对应bit
// 上位机: 直接写入整个power_ctrl值

// 如需本地按键优先，需额外逻辑:
// if(本地按键动作) 锁定对应bit不被上位机覆盖
```

## 验证结果
逻辑正确，理解按键与上位机的优先级关系

## 预防措施
- 本地控制和远程控制共用状态变量时需明确优先级
- XOR(翻转) vs 直接写入(覆盖)行为不同

## 经验规则
- 按键用XOR翻转，上位机用直接写入
- 两者共用变量时需考虑竞争条件
- 拨钮(自锁)需改为电平跟随而非边沿触发
