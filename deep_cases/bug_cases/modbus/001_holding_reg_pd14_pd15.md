# 001: HoldingReg 46控制PD14/PD15的ULN2003反向问题

## 项目
WSC-16 (STM32F103 + Modbus RTU + ULN2003继电器驱动)

## 环境
MCU: STM32F103, 通信: Modbus RTU, 驱动: ULN2003A(反向达林顿)

## 现象
Holding_Reg[46]=48时PD14/PD15=低电平，但用户期望灯亮

## 影响范围
上位机对桌面照明/灯带照明的控制逻辑

## 排查过程

### 假设1: 直接电平映射
- 验证方法：bit4=1→PD14=高→灯亮？
- 结果：**错误！** ULN2003A是反向器

### 假设2: ULN2003A反向特性
- 验证方法：查阅ULN2003A数据手册
- 结果：输入低→输出高阻（开路）；输入高→输出低（导通到GND）

## 根因
**ULN2003A是反向器+集电极开路输出**：
- PD14=低 → ULN2003A输出高阻 → 继电器线圈无电流 → 灯关
- PD14=高 → ULN2003A输出拉低 → 继电器线圈通电 → 灯亮

## 修改方案
```c
// 理解正确后无需改硬件，只需理解逻辑：
// power_ctrl bit=1 → MCU引脚高 → ULN2003A输出低 → 继电器吸合 → 灯亮
// power_ctrl bit=0 → MCU引脚低 → ULN2003A输出高阻 → 继电器断开 → 灯灭

// Holding_Reg[46] = 48 = 0x30 = bit4+bit5
// → PD14=高(桌面照明开), PD15=高(灯带照明开)
```

## 验证结果
逻辑正确，48=两个灯同时亮

## 预防措施
- 使用达林顿/ULN系列驱动时注意反向特性
- 集电极开路输出需外部上拉/电源才能形成回路

## 经验规则
- ULN2003A: 输入高=输出低(GND)，输入低=输出高阻
- 继电器线圈驱动电流由外部电源(12V/24V)提供
- 逻辑电平≠负载状态，中间有驱动电路时要考虑变换
