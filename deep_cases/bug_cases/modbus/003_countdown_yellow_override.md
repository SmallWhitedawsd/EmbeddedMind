# 003: 倒计时30秒时呼叫牌黄灯被绿灯闪烁覆盖

## 项目
WSC-16 (STM32F103 + 三色灯 + 485通信)

## 环境
MCU: STM32F103, 通信: HC433无线+RS485, 显示: 红/绿/黄三色灯

## 现象
倒计时30秒内有呼叫牌呼叫时，黄灯应该闪烁但被绿灯闪烁覆盖

## 影响范围
呼叫牌指示功能

## 排查过程

### 假设1: LED_Flag优先级问题
- 验证方法：分析StartTask01每秒执行顺序
- 结果：HC433_Event_Process先设LED_Flag=5(黄闪)，然后HC433_Call_Led_Process中倒计时≤30s会覆盖为LED_Flag=4(绿闪)

### 假设2: 条件判断逻辑
- 验证方法：分析HC_433.c:582-598
- 结果：倒计时30s时如果有呼叫，Now_Call_event!=0导致不进入else if，黄灯可以正常

## 根因
**执行顺序导致标志覆盖**：
```
1. HC433_Event_Process → LED_Flag=5 (黄闪)
2. HC433_Call_Led_Process → 倒计时≤30s → LED_Flag=4 (绿闪，无条件覆盖!)
```

## 修改方案
```c
// HC_433.c - 修复覆盖逻辑
if ((*start_tick - *end_tick <= 30) && (HC433.Now_Call_event == 0))
    HC433.LED_Flag = 4;  // 仅无呼叫时才绿闪
else if ((*start_tick - *end_tick > 30) && (HC433.Now_Call_event == 0))
    HC433.LED_Flag = 1;  // 常亮
// 有呼叫时保持LED_Flag=5(黄闪)不被覆盖
```

## 验证结果
倒计时30s内有呼叫时黄灯正常闪烁

## 预防措施
- 状态标志覆盖前检查是否有更高优先级事件
- 执行顺序影响逻辑结果时需加保护条件

## 经验规则
- 多个任务/函数写同一标志时需注意执行顺序
- 高优先级事件(呼叫)不应被低优先级事件(倒计时)覆盖
- 条件判断要覆盖所有分支
