# 004: Modbus寄存器26写权限被锁定(SRW)

## 项目
SX-MK-010-0140 (STM32F103 + Modbus RTU + 加密文件)

## 环境
MCU: STM32F103, 协议: Modbus RTU, 部分源码加密

## 现象
Modbus poll写寄存器26地址1和0无反应

## 影响范围
启动/停止控制功能

## 排查过程

### 假设1: 寄存器地址错误
- 验证方法：检查Modbus映射表
- 结果：寄存器26=set_start_step，地址正确

### 假设2: 写权限被锁定
- 验证方法：分析FCR_UserUpdate和SRW逻辑
- 结果：**写寄存器26需要先写reg14=1解锁写权限**

### 假设3: 加密文件影响
- 验证方法：检查哪些文件被加密
- 结果：Power_Manager/CountDown_*在加密文件中，但Control.c可读

## 根因
**写寄存器26需要先解锁**：
- reg14是写权限控制寄存器
- 写reg14=1 → SRW=RW（可写）
- 否则FCR_UserUpdate(SRW,26,...)走RO分支，用内部值覆盖写入值

## 修改方案
```c
// 正确操作顺序:
// 1. 先写 reg14=1 (解锁写权限)
// 2. 再写 reg26=1 (启动) 或 reg26=0 (停止)

// Modbus指令:
// 解锁: 01 06 00 0E 00 01 xxx
// 启动: 01 06 00 1A 00 01 xxx
// 停止: 01 06 00 1A 00 00 xxx
```

## 验证结果
先解锁再写reg26，功能正常

## 预防措施
- 写控制寄存器前检查是否有权限锁定
- 关键操作需先解锁再执行

## 经验规则
- Modbus寄存器常有读写权限分离
- RO寄存器写入会被内部值覆盖
- 控制寄存器常有"使能位"门控
