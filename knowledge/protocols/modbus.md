# Modbus RTU 命令格式

## 场景
485 三色灯控制，使用 Modbus RTU 协议。

## 现象/问题
需发送正确格式的 Modbus 命令控制设备。

## 根因分析
Modbus RTU 帧格式：地址(1) + 功能码(1) + 数据(N) + CRC(2)，CRC 低字节在前。

## 解决方案
```
开红灯:   01 06 00 64 00 01 09 D5
关红灯:   01 06 00 64 00 00 C8 15
开绿灯:   01 06 00 65 00 01 58 15
关绿灯:   01 06 00 65 00 00 99 D5
开黄灯:   01 06 00 66 00 01 A8 15
关黄灯:   01 06 00 66 00 00 69 D5
开蜂鸣器: 01 06 00 67 00 01 F9 D5
关蜂鸣器: 01 06 00 67 00 00 38 15
全部开启: 01 06 03 E8 00 01 C8 7A
全部关闭: 01 06 03 E9 00 01 99 BA
```

**帧解析**：
- `01` = 设备地址
- `06` = 功能码（写单寄存器）
- `00 64` = 寄存器地址（0x0064 = 100）
- `00 01` = 写入值
- `09 D5` = CRC16（低字节 0xD5 在前）

## 验证方法
发送命令后，设备回显相同帧表示成功。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# Modbus CRC16 校验算法

## 场景
生成或验证 Modbus RTU 帧的 CRC 校验码。

## 现象/问题
CRC 校验失败导致设备不响应。

## 根因分析
Modbus CRC16 使用多项式 0xA001（0x8005 的反转），初始值 0xFFFF。

## 解决方案
```c
// Modbus CRC16 计算
uint16_t Modbus_CRC16(uint8_t *data, uint8_t len) {
    uint16_t crc = 0xFFFF;
    for (uint8_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001)
                crc = (crc >> 1) ^ 0xA001;
            else
                crc >>= 1;
        }
    }
    return crc;
}

// 使用示例
uint8_t cmd[] = {0x01, 0x06, 0x00, 0x64, 0x00, 0x01};
uint16_t crc = Modbus_CRC16(cmd, 6);
// crc = 0x09D5 → 发送时低字节在前: D5 09
```

## 验证方法
发送 `01 06 00 64 00 01 09 D5`，设备回显相同帧。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# Modbus 寄存器映射设计

## 场景
SX-MK-010 电源控制模块，通过 Modbus 控制继电器和读取参数。

## 现象/问题
需了解各寄存器地址含义。

## 根因分析
寄存器映射在 MMU.c 中定义。

## 解决方案
| 地址 | 名称 | 说明 |
|------|------|------|
| 10 | Uc/Ic(单相) 或 Usum/Isum(三相) | 电压/电流 |
| 14 | SRW | 写权限控制（1=解锁写入） |
| 26 | set_start_step | 启动/停止控制（1=启动, 0=停止） |
| 44 | card_status | 卡状态（0=已充值） |

**写 reg14=1 解锁写权限**（SRW=RW）。

## 验证方法
发送写命令后读取寄存器，确认值已更新。

## 来源
SX-MK-010 - 探索两个代码目录结构 (2026-07-10)

# Modbus 停止命令与屏幕同步 BUG

## 场景
Modbus 地址 26 写 0 停止继电器，但触摸屏按钮状态不同步。

## 现象/问题
Modbus 停止后，触摸屏仍显示"运行中"。

## 根因分析
倒计时结束停止路径有 `home.bt222.val=1` 同步，但 reg26=0 停止路径缺失。

## 解决方案
```c
// Control.c - set_start_step==0 块中插入
if (set_start_step == 0) {
    Power_Manager(0);
    // 新增：同步屏幕按钮状态
    Uart3_SendBuff("home.bt222.val=1", ...);
    experiment_duration = 0;  // 阻止 RFID 重启动
}
```

**注意**：文件为 GB2312 编码，需字节安全编辑。

## 验证方法
Modbus 写 reg26=0 后，触摸屏按钮变为"停止"状态。

## 来源
SX-MK-010 - 阅读单相和三相版本BUG代码 (2026-07-10)

# Modbus 读写命令构造

## 场景
通过串口助手调试 Modbus 设备。

## 现象/问题
需构造读/写命令测试设备。

## 根因分析
读保持寄存器功能码 0x03，写单寄存器 0x06。

## 解决方案
```powershell
# 读寄存器 0x0064（功能码 03）
# 请求: 01 03 00 64 00 01 CRC
$data = @(0x01, 0x03, 0x00, 0x64, 0x00, 0x01)
# CRC 计算后: 01 03 00 64 00 01 D5 CA

# 写寄存器 0x0064 = 1（功能码 06）
# 请求: 01 06 00 64 00 01 CRC
$data = @(0x01, 0x06, 0x00, 0x64, 0x00, 0x01)
# CRC 计算后: 01 06 00 64 00 01 09 D5
```

**读命令响应格式**：
```
01 03 02 XX XX CRC
地址 功能 字节数 数据 CRC
```

## 验证方法
发送读命令，设备返回寄存器值。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# 全部关闭指令的副作用

## 场景
发送 `01 06 03 E9 00 01 99 BA`（全部关闭）后，红灯无法再点亮。

## 现象/问题
全部关闭后，单独开红灯指令失效。

## 根因分析
全部关闭寄存器 0x03E9 可能锁死后续单个寄存器写入。

## 解决方案
```c
// competition() case 2 - 去掉 all_off
case 2:  // 红灯+蜂鸣器
    // 去掉: send_cmd(all_off);  // 01 06 03 E9 00 01 99 BA
    send_cmd(red_on);      // 01 06 00 64 00 01 09 D5
    send_cmd(buzzer_on);   // 01 06 00 67 00 01 F9 D5
    break;
```

## 验证方法
先发送全部关闭，再发送开红灯，确认红灯能亮。

## 来源
WSC-16 - UART5 RS485 control logic (2026-06-23)
