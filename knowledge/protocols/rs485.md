# RS485 半双工收发切换

## 场景
STM32 UART5 通过 RS485 适配器控制三色灯。

## 现象/问题
发送命令后无响应。

## 根因分析
RS485 半双工需要方向控制：发送时使能 TX，发送完后切换回 RX。

## 解决方案
```c
// 方法1：RTS 硬件自动控制（推荐）
// 配置 UART 的 RTS 引脚为 RS485 方向控制
huart5.AdvFeatureInit = UART_ADVFEATURE_RXOVERRUNDISABLE_INIT;
// 部分 USB-RS485 适配器自动处理方向

// 方法2：手动 GPIO 控制方向
void RS485_Send(uint8_t *data, uint16_t len) {
    HAL_GPIO_WritePin(RS485_DE_GPIO_Port, RS485_DE_Pin, GPIO_PIN_SET);  // TX mode
    HAL_UART_Transmit(&huart5, data, len, 100);
    HAL_GPIO_WritePin(RS485_DE_GPIO_Port, RS485_DE_Pin, GPIO_PIN_RESET); // RX mode
}

// 方法3：软件 RTS 控制（部分适配器）
sp.RtsEnable = true;
sp.Write(buf, 0, buf.Length);
sp.RtsEnable = false;
```

## 验证方法
示波器抓 RS485 A/B 差分信号，确认发送后有响应波形。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# RS485 硬件接线与终端电阻

## 场景
RS485 总线连接多个设备。

## 现象/问题
通信不稳定，偶发丢包。

## 根因分析
- A/B 线接反导致无法通信
- 长距离总线缺少终端电阻导致信号反射

## 解决方案
```
接线规范：
1. A 接 A，B 接 B（不要交叉）
2. 总线两端各加 120Ω 终端电阻
3. 屏蔽层单端接地

短距离（<1m）可省略终端电阻。
```

## 验证方法
万用表测量 A-B 电压，空闲时应为负（-200mV ~ -600mV）。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# RS485 收发切换延迟

## 场景
发送完数据后立即切回接收模式，错过设备响应。

## 现象/问题
发送命令后无响应。

## 根因分析
USB-RS485 适配器发完数据后需要留足够时间收应答。

## 解决方案
```powershell
# PowerShell 调试脚本
$sp.RtsEnable = $true   # 使能发送
Start-Sleep -Milliseconds 20  # 等待方向切换稳定
$sp.Write($buf, 0, $buf.Length)
$sp.Flush()             # 等待发送完成
$sp.RtsEnable = $false  # 切回接收
Start-Sleep -Milliseconds 500  # 等待设备响应
```

**关键延迟**：
- 方向切换后：~20ms 稳定时间
- 发送完成后：等待最后一个字节移位完毕（9600bps 下 1字节≈1ms）
- 设备响应：100-500ms

## 验证方法
发送命令后等待 500ms，检查是否有数据返回。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# RS485 与 433 无线模块混合组网

## 场景
433 无线模块通过 USART2 接收数据，控制 RS485 三色灯倒计时。

## 现象/问题
433 模块发送的无线包需转发到 RS485 总线。

## 根因分析
- 433 模块：USART2 @ 1200bps
- RS485 灯：UART5 @ 9600bps
- 需协议转换和速率匹配

## 解决方案
```c
// HC_433.c - 解析 433 协议后转发到 RS485
void HC433_ParseAndForward(void) {
    // 解析 GTI 协议帧
    if (strstr(USART2_Buffer, "GTI") != NULL) {
        uint16_t countdown = (USART2_Buffer[4] << 8) | USART2_Buffer[5];
        countdown /= 10;  // 时间单位 0.1s
        
        // 转发到 RS485 控制三色灯
        competition(USART2_Buffer[LED_Flag]);
    }
}
```

## 验证方法
433 发送倒计时包，观察三色灯按预期闪烁。

## 来源
WSC-16 - UART5 RS485 control logic (2026-06-23)

# RS485 通信参数配置

## 场景
485 三色灯默认通信参数。

## 现象/问题
需确认波特率、数据位、校验位。

## 根因分析
设备出厂默认参数固定。

## 解决方案
```
485 默认参数：
- 波特率: 9600
- 数据位: 8
- 停止位: 1
- 校验位: 无
- 协议: Modbus RTU
```

```c
// STM32 UART5 配置
huart5.Instance = UART5;
huart5.Init.BaudRate = 9600;
huart5.Init.WordLength = UART_WORDLENGTH_8B;
huart5.Init.StopBits = UART_STOPBITS_1;
huart5.Init.Parity = UART_PARITY_NONE;
huart5.Init.Mode = UART_MODE_TX_RX;
HAL_UART_Init(&huart5);
```

## 验证方法
发送 `01 06 00 64 00 01 09 D5`，设备回显相同帧。

## 来源
WSC-16 - Serial protocol debug no response (2026-06-23)

# 电阻屏 UART 受 RFID 干扰

## 场景
刷卡（MFRC522 13.56MHz）后触摸屏停止按钮偶尔失效。

## 现象/问题
刷卡后按停止键继电器有概率不停止。

## 根因分析
1. 电阻屏触摸控制器通过 ADC 检测触摸，刷卡期间可能触发误触摸
2. MFRC522 产生强电磁场，对电阻屏 ADC 线路造成干扰
3. USART3 RX 使用单字节中断接收，无硬件抗干扰措施

## 解决方案
```c
// 方案1：帧长度校验
void Uart3_TJC_Manage(void) {
    if (rx_len > MAX_FRAME_LEN) {
        rx_len = 0;  // 丢弃异常帧
        return;
    }
}

// 方案2：刷卡后延迟处理屏幕命令
void RFID_Process(void) {
    // 刷卡处理...
    osDelay(200);  // 避开 RFID 干扰窗口
}
```

## 验证方法
连续刷卡 20 次后按停止键，确认 100% 生效。

## 来源
SX-MK-010 - 触摸屏停止按钮继电器失效问题 (2026-07-10)
