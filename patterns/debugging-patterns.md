# 调试模式库

## 模式1: 上电启动异常

### 现象
首次上电正常, 短时间断电再上电启动失败/延迟

### 定位
1. 读RCC_CSR (0x40023874) 判断复位原因
2. bit29=IWDG复位 → 代码死等
3. bit27=POR复位 → 正常上电
4. 测量VCC上升沿是否有纹波

### 根因
- 大电容缓放电路导致VDD未跌到POR阈值以下
- 内部状态不确定, 初始化死等无超时
- 放电电阻缺失/阻值过大

### 解决
1. 加放电电阻到VDD对地 (1kΩ/0805, τ=RC)
2. 初始化函数加超时返回
3. 上电沉降窗口 (1.5s, 每100ms喂狗)
4. 重试机制 + 兜底整机复位

### 验证
```powershell
# 3分钟监听, 每6秒读RCC_CSR
$end = (Get-Date).AddMinutes(3)
while ((Get-Date) -lt $end) {
  & "ST-LINK_CLI.exe" -c ID=0 SWD HOTPLUG -r32 0x40023874 1
  Start-Sleep -Seconds 6
}
```

## 模式2: 屏幕刷新率/通信速率升级失败

### 现象
SPI波特率从/32改到/16后黑屏/花屏

### 定位
1. 确认排线长度 (20cm FPC软排线)
2. 示波器看SCK/MOSI信号完整性
3. 检查是否有振铃/反射

### 根因
- 长排线+高速信号 → 信号完整性问题
- 阻抗不匹配 → 反射/振铃

### 解决
1. 回退到能用的波特率
2. 降低GPIO压摆率 (SPEED_LOW) 减少反射
3. 如硬件允许, 缩短排线或加终端电阻

### 验证
- 稳定显示≥5分钟无花屏

## 模式3: 触屏/输入响应卡顿

### 现象
首次上电触屏卡顿, 多次上电后流畅

### 定位
1. 检查是否有taskENTER_CRITICAL包裹I2C/SPI操作
2. 检查ISR频率 (AD7606 200kHz采样)
3. 检查DMA总线竞争

### 根因
- 高频ISR打断低速通信 (软件I2C)
- DMA总线竞争导致通信异常
- 系统进入低扫描率模式

### 解决
1. 移除taskENTER_CRITICAL
2. 降低高频任务频率 (200Hz→20Hz)
3. GUI_Task周期放宽 (1ms→5ms)

### 验证
- 连续操作触屏≥50次无卡顿

## 模式4: Modbus设备无应答

### 现象
发送正确Modbus RTU指令, 设备无返回

### 定位
1. 确认串口参数 (波特率/数据位/停止位/校验)
2. 确认设备地址和寄存器地址
3. 检查485 A/B线是否接反
4. 检查RS485收发切换时序 (RTS)
5. 确认COM端口未被占用

### 根因
- RS485半双工收发切换延迟不足
- RTS控制信号时序错误
- 应答等待时间过短

### 解决
1. 发送后RTS拉低, 等待≥500ms收应答
2. 检查设备管理器确认实际COM号
3. 用串口助手先排除硬件问题

### 验证
```powershell
$sp.RtsEnable = $true
Start-Sleep -Milliseconds 20
$sp.Write($buf, 0, $buf.Length)
$sp.RtsEnable = $false
Start-Sleep -Milliseconds 500
# 读应答
```

## 模式5: 状态机时序错乱

### 现象
倒计时结束, 红灯+蜂鸣器不工作

### 定位
1. 追踪状态变量赋值时序
2. 检查osDelay是否阻塞关键状态切换
3. 检查ISR中是否修改了状态变量

### 根因
- osDelay阻塞期间, 计数器继续运行
- 状态变量更新时序错乱
- 唤醒时条件已不满足

### 解决
1. 状态变量更新移到阻塞之前
2. 使用标志位+轮询替代长阻塞
3. 关键状态切换用原子操作

### 验证
- 连续10次倒计时, 每次红灯+蜂鸣器均正确触发

## 模式6: 电磁干扰导致控制失灵

### 现象
刷卡后按停止键继电器有概率不停止

### 定位
1. 对比电阻屏/电容屏差异
2. 检查RFID工作时串口波形
3. 检查USART帧是否有乱码

### 根因
- MFRC522 13.56MHz强电磁场干扰电阻屏ADC
- 串口接收乱码破坏停止命令帧
- 电阻屏误触发覆盖停止命令

### 解决
1. 软件: 帧长度校验, 丢弃异常帧
2. 协议: 命令重发机制
3. 硬件: UART线路滤波/屏蔽
4. 时序: 刷卡后延迟100-200ms处理屏幕命令

### 验证
- 连续刷卡+停止≥20次, 100%可靠

## 模式7: 看门狗超时分析

### 现象
系统不定期复位, 约30s间隔

### 定位
1. 读RCC_CSR bit29 (IWDGRSTF)
2. 确认IWDG超时计算: T = Prescaler/(LSI/Reload)
3. 检查IWDG喂狗点

### 根因
- 初始化函数无喂狗
- 死循环无超时
- 喂狗点位置不当

### 解决
1. 初始化全程喂狗
2. 死循环加超时退出
3. 重试机制 + 兜底复位

### 验证
```c
// IWDG配置
Prescaler = 256, Reload = 3750
超时 = 32000/256/3750 = 30s
```

## 模式8: 竞态条件导致状态覆盖

### 现象
停止后重刷RFID卡, 继电器又吸合

### 定位
1. 追踪停止路径和刷卡路径的共享变量
2. 检查停止后是否有残留状态

### 根因
- 停止后experiment_duration未清零
- 刷卡检查experiment_duration>0 → 重启

### 解决
1. 每个停止点后清零关键状态变量
2. 增加set_start_step!=0检查

### 验证
- 停止后刷卡, 继电器不吸合

---

## 模式9: 串口屏按键无响应

### 现象
按屏幕按钮, MCU无反应

### 定位
1. 串口助手监听屏幕发送数据
2. 确认MCU是否收到正确帧
3. 检查帧解析逻辑

### 根因
- 上电后需按复位键
- 帧头/帧尾不匹配
- 波特率不一致

### 验证
- 复位后按按钮, 串口助手确认数据发出

## 模式10: 编译/烧录失败

### 现象
Keil编译报错或Flash下载失败

### 定位
1. 检查scatter文件路径
2. 检查Flash算法是否添加
3. 检查ST-Link连接

### 解决
1. 修正.sct文件路径
2. 添加对应MCU Flash算法
3. 重新连接ST-Link

### 验证
- Build 0 Error, Flash Download成功
